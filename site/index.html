Render Pts.js scenes in Node.

pts-cli uses skia-canvas to render portable Pts scenes and compatible classic demos. It writes raster images and SVG without starting a browser.

ptsjs render scene.mjs --json
PNG, JPEG, WebP, raw RGBA, SVG
Node 20+, CPU renderer by default, preview 0.1

Overview

Sources
Portable scene modules and a manifest-tested subset of unchanged classic Pts demos.
Runtime
Pts and skia-canvas run in a fresh worker with a hard timeout and resource limits.
Output
Multiple raster and SVG files can be encoded from the same final canvas.
State
Time, frames, pointer input, event timelines, scene parameters, and randomness are explicit.
Automation
Atomic file writes and one JSON result containing paths, sizes, hashes, and errors.

Portable scenes

A portable scene is a default-exported object. Its setup callback receives Pts, space, form, parameters, and asset helpers. The same scene object can run in Node or mount in a browser.

orbit.mjs 
export default {
  apiVersion: 1,
  width: 720,
  height: 440,
  background: "#10283a",

  setup({ Pts, space, form, params }) {
    const { Circle } = Pts;
    const radius =
      Number(params.radius ?? 56);

    space.add((time) => {
      form
        .fillOnly("#7566ff")
        .circle(
          Circle.fromCenter(
            space.pointer,
            radius +
              Math.sin(time / 800) * 8
          )
        );
    });
  }
};
CLI 
ptsjs render orbit.mjs \
  --pointer 360,220 \
  --frame 60 --fps 60 \
  --param radius=56 \
  --out orbit.png \
  --out orbit.svg \
  --json
Browser 
import { mountScene } from
  "pts-cli/browser";
import scene from "./orbit.mjs";

const mounted =
  await mountScene(scene, {
    target: "#pt"
  });

// await mounted.dispose();

Scene dimensions replace Pts.quickStart. The runner replaces bindMouse().play(). Code inside space.add() remains ordinary Pts drawing code.

Raster and SVG output

Each requested format is encoded from the same final canvas. A single render may write several outputs.

Raster

Density, JPEG/WebP quality, transparency, and matte are configurable.

SVG

Text may be preserved or converted to paths. Raster images remain embedded rasters.

Atomic writes

Existing files are protected unless --force is supplied.

Deterministic rendering

The clock, input, scene parameters, and random seed can be supplied explicitly. Native pixels and fonts may still vary across platforms.

--time <ms>
Render one frame at the timestamp with a zero delta.
--frame <index> --fps <rate>
Simulate every frame from zero through the index.
--pointer <x>,<y>
Set initial pointer state without dispatching an action.
--events <file.json>
Replay move, down, drag, up, and resize events by timestamp.
--seed <string>
Seed Pts randomness and the worker's Math.random stream.
--param <key=value>
Override a named scene parameter. The flag is repeatable.

Source compatibility

New scenes should use the portable module format. The classic loader supports a tested subset of existing Pts demos.

Source Loader Behavior Browser reuse
Portable scene scene Default-exported object with explicit setup and dimensions. Mount the same object with pts-cli/browser.
Classic demo pts-demo Supplies Pts globals, Pts.quickStart, and a bounded CanvasSpace facade. The original compatible browser demo remains unchanged.

The compatibility layer is not a DOM emulator. HTMLSpace, SVGSpace, audio, microphone, video, editable pixel workflows, and arbitrary browser timers are outside its boundary. SVG file output remains available because it records Canvas drawing commands. Scene modules execute arbitrary JavaScript and should be treated as trusted code.

Run from this repository

The current package is a private 0.1 preview. The package name is pts-cli; the executable is ptsjs.

Shell 
$ git clone https://github.com/williamngan/skia-pts-canvas.git
$ cd skia-pts-canvas
$ pnpm install && pnpm build
$ node dist/cli.mjs render examples/basic-card.mjs --json
